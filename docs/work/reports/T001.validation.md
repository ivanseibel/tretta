## Achados reproduzidos

### Mão de jogador armazenada no protótipo

Em `packages/rules/src/round.ts`, a inicialização de `hands` com `{}` seguida de atribuição pelo id interpreta `__proto__` como mudança de protótipo. O id passa na validação e a função retorna, mas sua mão não aparece em `Object.keys`, `Object.values` ou JSON.

Reprodução: `startRound({ playerIds: ['__proto__', 'ana'], random: createSeededRandom(1) })`. Resultado observado: `Object.keys(hands)` contém apenas `ana`, `Object.hasOwn(hands, '__proto__')` é falso, e a mão de sete cartas desaparece após JSON. A representação deve guardar cada jogador como propriedade própria, inclusive ids que coincidam com nomes de propriedades de objetos.

### Abertura sem garantia de término

O laço que devolve uma carta não numérica e reembaralha pode recolocar a mesma carta no topo indefinidamente. A condição de existência de uma numérica na pilha não garante progresso.

Reprodução com as 108 cartas: retirar o primeiro coringa de `createClassicDeck()` e inseri-lo no índice 14; chamar `dealRound` para `['ana', 'bia']` com a fonte abaixo. Depois de distribuir, a pilha tem 94 cartas e cada embaralhamento consome 93 valores. A fonte mantém o mesmo coringa no topo:

```ts
let calls = 0;
const random = () => calls++ % 93 === 0 ? 0 : 0.999;
```

O processo não terminou em dois segundos e foi encerrado. Um caso mínimo também reproduz: 14 cartas para as mãos, uma ação, uma numérica e `random: () => 0`.

Correção delimitada pelo orquestrador: reservar temporariamente as não numéricas até encontrar a primeira numérica; devolver as reservadas à pilha restante e reembaralhar uma única vez, quando houver devoluções. Assim, nenhuma carta rejeitada pode reaparecer durante a busca. Sem numérica disponível, manter o erro explícito. Essa escolha preserva o destino proposto pelo executor e os requisitos de T001.
